# SECTION B - API Endpoint Plan
---
## How authentication works

RaceDay uses server-side sessions. When a user logs in, the API checks their password and saves their user ID and role in a session on the server. The browser keeps the session cookie (.RaceDay.Session) and sends it with every request. The API gets the user ID and role from the session, not from the request body.

- 401 Unauthorized - the user is not logged in
    
- 403 Forbidden - the user has the wrong role or the data belongs to someone else
    

## Roles used in the table

|Role|Meaning|
|---|---|
|None|Anybody can call it, no login needed|
|Any|The user must be logged in, regardless of their role|
|Organiser|Only a logged in user with the Organiser role|
|Participant|Only a logged in user with the Participant role|

| ----------- | ------------------ | ------------------------------------------------------------------------------------ | ------------- | ---------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| POST        | /api/auth/register | Creates a new account with the role the user picks and saves a hash of the password. | None          | { firstName, lastName, email, password, phoneNumber, dateOfBirth, roleName } | 201 Created - the new userId, email and roleName  <br>  <br>400 Bad Request - a field is missing, the email is not valid, the password is shorter than 8 characters, the role is not Organiser or Participant, or the date of birth is in the future  <br>  <br>409 Conflict - the email is already registered |

| POST        | /api/auth/logout   | Ends the session of the logged in user.                                              | Any           | None                                                                         | 200 OK - the session was cleared on the server  <br>  <br>401 Unauthorized - not logged in                                                                                                                                                                                                                     |

**Query string of GET /api/events** (all optional and can be combined):

|Parameter|Meaning|
|---|---|
|search|Text to look for in the event name, description or location.|
|eventType|Running, Walking or Cycling. The values run, walk and cycle are also accepted.|
|province|The province of the event, for example KwaZulu-Natal.|
|upcomingOnly|true leaves out events that have already taken place. The default is false.|
